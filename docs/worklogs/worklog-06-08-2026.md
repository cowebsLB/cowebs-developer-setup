# Worklog - 06-08-2026

## Summary

Created COWebs.lb Master Developer Environment Setup v4.0.0 by consolidating all three prototype scripts into one branded, testable, and documented Windows batch application.

## Why

The prototypes contained complementary profiles and setup behavior, but also stale Winget identifiers, repeated completion/restart prompts in aggregate profiles, unreliable post-install command discovery, weak failure propagation, and inconsistent branding.

## How

Implemented install-only profile subroutines, a central dispatcher, a shared exact-ID installer, one post-install PATH refresh, opt-in configuration, append-only logging, summary counters, deterministic exit codes, and safe CLI dry-run execution.

## When

## Changes Made

- Added nine selectable profiles and preserved every package represented across the prototypes.
- Corrected Miniconda, JupyterLab, Python, PostgreSQL, and Godot package IDs.
- Added exact Winget matching, dry-run mode, CLI profile selection, PATH refresh, optional configuration, workspace setup, append-only logs, and branded summaries.
- Added structured documentation and an automated non-installing verification suite.

## Problems Encountered

- The first generated batch file used LF line endings, causing `cmd.exe` to fail resolving the `:Install` label.
- The initial Everything test expected 52 package calls instead of the actual 56 entries across all component profiles.

## Solutions

- Converted `master-setup.bat` to Windows CRLF line endings.
- Corrected the aggregate traversal assertion to 56 package entries.

## Bugs Found

- Prototype aggregate profiles entered completion or restart handling after every component profile.
- v3 exited on invalid menu input.
- Several Winget IDs were stale or too generic.
- Optional commands could run before the current process received updated PATH values.
- Prototype logs were overwritten or incomplete, and failures were not propagated reliably.

## Bug Fixes

- Component profiles now return with `exit /b`; finalization runs once.
- Interactive selection uses validated `choice` input, while CLI input has explicit error codes.
- Current exact package IDs and `--exact --source winget` are used.
- PATH refresh and command availability checks precede optional configuration.
- Logs append sessions, exclude credentials, and include package failure status.

## Testing

- Unit Tests: Static assertions for version, flags, labels, package IDs, exact matching, and stale-ID removal passed.
- Integration Tests: `everything` dry-run traversed all 56 package entries and reached one final summary with exit code 0.
- End-to-End Tests: Safe CLI dry-runs for all nine profiles and invalid-profile handling passed; real package installation was not run on the active workstation.
- Manual Testing: Reviewed branded output, summary content, CRLF encoding, and documentation links.
- Coverage Summary: All nine dispatchers, all 26 distinct package IDs, aggregate control flow, dry-run safety, and principal error handling are covered.
- Edge Cases Tested: Invalid profile, non-elevated dry-run, duplicate package declarations in aggregate profiles, and Windows batch label resolution.

## Performance Notes

Aggregate profiles still query repeated package IDs, but installed-package checks prevent duplicate installations. A future data-driven manifest could remove repeated queries. Dry-run completes in under a second on the development machine.

## Advanced Warnings

- Real installation remains dependent on current Winget manifests, package installer behavior, network availability, and package-specific elevation.
- Python 3.14 and PostgreSQL 18 are intentionally version-pinned and require a future version-policy update.
- Real-install validation should occur in Windows Sandbox or a disposable VM before public distribution.
- The folder is not currently a Git repository, so no commit or CI verification exists.

## Summary

## Changes Made

- Added the full six-line COWEBS banner.
- Enabled UTF-8 console rendering.
- Bumped the release from 4.0.0 to 4.0.1.
- Documented terminal compatibility and added branding tests.

## Problems Encountered

- The earlier prototype stored UTF-8 artwork without selecting a matching console code page, which could render as mojibake.
- Initial UTF-8 initialization could leave the calling console on code page 65001 after the batch process ended.

## Solutions

- The master script now executes `chcp 65001` before rendering any branded output.
- The original code page is captured first and restored on every top-level exit path.

## Bugs Found

- The first branding revision changed shared console state without restoring it.

## Bug Fixes

- Corrected the console encoding mismatch responsible for the prototype banner rendering problem.
- Restored the caller's original code page after success, help, cancellation, argument errors, preflight errors, and profile errors.

## Testing

- Unit Tests: Banner content, version, UTF-8 initialization, package coverage, labels, documentation, and CRLF assertions passed.
- Integration Tests: All nine CLI profile dry-runs passed.
- End-to-End Tests: Everything dry-run and invalid-profile handling passed without system changes.
- Manual Testing: Branded header output was captured from `cmd.exe` and inspected.
- Coverage Summary: Branding startup plus the complete existing setup regression suite are covered.
- Edge Cases Tested: UTF-8 batch content with required Windows CRLF label handling.

## Performance Notes

The code-page change adds negligible startup time and does not affect installation behavior.

## Advanced Warnings

- Legacy console fonts may not include the required block and box-drawing glyphs even with UTF-8 enabled.
- Real package installation remains intentionally untested on the active workstation.
