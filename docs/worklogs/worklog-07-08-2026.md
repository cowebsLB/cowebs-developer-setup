## Summary

Re-architected COWebs.lb Developer Setup v5.0.0 as a cross-platform-ready repository with a single-file verified Windows bootstrap, shared JSON manifests, a Windows PowerShell adapter, release tooling, automated tests, and GitHub Actions.

## Why

The monolithic BAT repeated package/profile logic and could not scale cleanly to macOS, Ubuntu, and Fedora. Requiring the BAT to clone a repository would also create a circular Git dependency and expose users to mutable default-branch code.

## How

Converted the BAT into a branded release bootstrap. It downloads a tagged ZIP, verifies a pinned SHA-256, extracts to a randomized session directory, invokes the platform adapter, stores logs outside the payload, and deletes only its exact temporary directory. Package keys and profiles moved to JSON; Windows behavior moved to PowerShell.

## Changes Made

- Added 26 logical packages with exact Windows mappings.
- Added nine inherited, duplicate-free shared profiles.
- Added the Windows installation and configuration adapter.
- Added a checksum-pinned, self-cleaning single-file bootstrap.
- Added macOS, Ubuntu, and Fedora extension boundaries.
- Added release building, CI, manifest tests, nine engine dry-runs, and complete bootstrap simulation.
- Added MIT licensing and repository-specific contributor guidance.
- Added explicit cross-platform line-ending rules: CRLF for BAT and LF for scripts, manifests, workflows, and documentation.
- Created the public `cowebsLB/cowebs-developer-setup` GitHub repository and published release `v5.0.0` with the BAT and verified runtime ZIP.

## Problems Encountered

- PowerShell strict mode rejected missing optional `extends` properties on leaf profiles.
- The initial Full Stack test expectation counted 14 packages instead of 13 unique packages.
- A repository clone was unsuitable because Git may not exist before setup.
- The Windows Git configuration would otherwise normalize future cross-platform source files to CRLF.

## Solutions

- Accessed optional JSON properties through `PSObject.Properties`.
- Corrected the Full Stack expectation after verifying de-duplication across Backend and Frontend.
- Used a pinned GitHub release ZIP with SHA-256 verification instead of Git clone.
- Added `.gitattributes` so each file type has a platform-safe committed line ending.

## Bugs Found

- Monolithic profiles repeated package checks in composite profiles.
- Temporary cleanup and durable logs were coupled in the earlier single-file design.
- The architecture had no stable package-key abstraction for additional operating systems.

## Bug Fixes

- Profile inheritance now resolves each logical package once.
- Logs are created under `%LOCALAPPDATA%` before temporary cleanup.
- Shared manifests define stable intent while adapters own platform behavior.
