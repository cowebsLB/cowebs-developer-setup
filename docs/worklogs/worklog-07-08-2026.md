## Summary

Re-architected COWebs.lb Developer Setup v5.0.0 as a cross-platform-ready repository with a single-file verified Windows bootstrap, shared JSON manifests, a Windows PowerShell adapter, release tooling, automated tests, and GitHub Actions.

## Why

The monolithic BAT repeated package/profile logic and could not scale cleanly to macOS, Ubuntu, and Fedora. Requiring the BAT to clone a repository would also create a circular Git dependency and expose users to mutable default-branch code.

## How

Converted the BAT into a branded release bootstrap. It downloads a tagged ZIP, verifies a pinned SHA-256, extracts to a randomized session directory, invokes the platform adapter, stores logs outside the payload, and deletes only its exact temporary directory. Package keys and profiles moved to JSON; Windows behavior moved to PowerShell.

## Summary

Fixed the Windows GitHub Actions bootstrap failure by removing its dependency on PowerShell module auto-loading and added a regression test for the runner condition.

## Why

GitHub Actions run `31128598613` checked out the published v5 commit and failed with bootstrap exit code `5` because the child `powershell.exe` process could not resolve `Get-FileHash`. The workflow-level Node 20 deprecation message was unrelated and did not cause the failure.

## How

Replaced the three bootstrap module-dependent operations with framework APIs: `System.Net.WebClient` for the tagged release download, `System.Security.Cryptography.SHA256` for streaming hash calculation, and `System.IO.Compression.ZipFile` for extraction. Updated the integration test to replace `PSModulePath` with an empty directory before invoking the real BAT.
