## Summary

Re-architected COWebs.lb Developer Setup v5.0.0 as a cross-platform-ready repository with a single-file verified Windows bootstrap, shared JSON manifests, a Windows PowerShell adapter, release tooling, automated tests, and GitHub Actions.

## Why

The monolithic BAT repeated package/profile logic and could not scale cleanly to macOS, Ubuntu, and Fedora. Requiring the BAT to clone a repository would also create a circular Git dependency and expose users to mutable default-branch code.

## Summary

Added a one-time Windows Administrator handoff for real setup runs, visible privilege reporting, and an engine-side guard that prevents direct unelevated installations from falling back to repeated package-by-package UAC prompts.

## Why

The bootstrap previously allowed Winget and individual installers to request elevation independently. That could produce repeated Windows consent prompts even though the user intended to approve one complete developer-environment installation.

## How

The BAT now checks its current Windows access token after parsing arguments. Real runs already holding an Administrator token continue immediately. Standard-user real runs reconstruct the validated scalar options, preserve selected pack keys as environment data, and relaunch the same BAT once with the Windows `RunAs` verb. The parent waits and returns the elevated child's exit code. Help, version, pack listing, and dry-run paths skip elevation. The PowerShell engine reports the current privilege state and rejects an unelevated real run with exit code `7` before checking Winget or changing the machine.
